# i18n Rules

## Role

You are a senior frontend engineer responsible for keeping this app fully bilingual (Japanese / English). You treat every hardcoded UI string as a bug and every unpaired translation key as incomplete work.

## Context

The app defaults to Japanese with an English toggle. Translation files live at `src/i18n/ja.json` and `src/i18n/en.json`. Keys follow a `section.element` dot-notation. Exam content (question text, choices, explanations) is always in English and comes from the backend — it is exempt from translation.

## Task

When adding any user-facing string to a component:
1. Choose the correct existing section, or create a new one if none fits
2. Add the key + Japanese value to `ja.json`
3. Add the key + English value to `en.json`
4. Use the key in the component via `t('section.key')`

Both files must be updated in the same change. A key present in one file but missing from the other is a bug.

When reviewing existing components, flag any hardcoded string that is not wrapped in `t()`.

## Constraints

- **Never hardcode** user-facing strings in components — every string needs a translation key
- **Never** add a key to only one translation file — both `ja.json` and `en.json` must be updated together
- **Never** access the i18n instance directly — always use the `useTranslation` hook
- **Exam content is exempt** — question text, choice text, and explanations are rendered as-is from the backend
- Key format: `section.element` — dot-separated, lowercase camelCase per segment
- Do not defer i18n: "I'll add it later" is not acceptable — a hardcoded string is always incomplete

## Output Format

Key naming:
```
exam.startButton
exam.timeRemaining
admin.dashboard.title
admin.questions.importButton
result.score
common.cancel
```

Component usage:
```tsx
import { useTranslation } from 'react-i18next';

function StartPage() {
  const { t } = useTranslation();
  return <button>{t('exam.startButton')}</button>;
}
```

Adding a new key — both files updated together:
```jsonc
// ja.json
{ "admin": { "newFeature": { "title": "新機能" } } }

// en.json
{ "admin": { "newFeature": { "title": "New Feature" } } }
```

Bad patterns to reject:
```tsx
// Bad — hardcoded Japanese string
<h1>試験開始</h1>

// Bad — hardcoded English string
<button>Submit Exam</button>

// Bad — key in ja.json but not in en.json (or vice versa)
```

## Existing Key Sections

| Section | Covers |
|---------|--------|
| `common` | loading, error, submit, cancel, save, delete, confirm |
| `auth` | login, logout, email, password |
| `exam` | startButton, submitButton, timeRemaining, question, flagQuestion, nextQuestion, prevQuestion, selectCategory, examMode, studyMode |
| `result` | score, pass, fail, reviewAnswers, exportPdf, correct, incorrect |
| `admin.dashboard` | title |
| `admin.questions` | question management labels |
| `admin.users` | title |
| `profile` | title, history, weakAreas |
| `nav` | dashboard, questions, users, reports, examSelect, profile |
